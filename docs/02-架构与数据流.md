# 架构与数据流

## 三层职责

| 层 | 位置 | 谁维护 | 用途 |
|---|---|---|---|
| 原始资料 | `raw/` | 用户收集，Codex 仅维护状态 | 保留事实来源与附件 |
| 用户笔记 | `notes/` | 用户拥有大纲，Codex 可扩写正文 | 课堂、会议、方法和个人思考 |
| 知识 Wiki | `wiki/` | Codex 与用户共同维护 | 跨来源的可链接结论 |

不要把 Wiki 当作 Raw 的复印件，也不要因为想整洁而删除 Raw。Raw 是可追溯性，Wiki 是可复用性。

## Raw 的文件与批次

- 新 Clip 直接进 `raw/unprocessed/` 根目录。
- 处理前可以新建子文件夹，把 2–5 个明确相关的 Clip 与附件组成一个临时批次。
- 同名 PDF、frontmatter `attachments` 指向的文件，或相同 `ingest_group` 的资料，随 Markdown 一起构成一个 ingest 单元。
- 批次批准后整组移入 `raw/processed/`，保持目录结构。

## Wiki 的四类页面

| 位置 | 页面角色 | 适合放什么 |
|---|---|---|
| `wiki/sources/` | 证据节点 | 单篇网页、文章、会议记录的来源摘要 |
| `wiki/literature-synthesis/` | 综合节点 | 多来源结论、比较、争议、局限 |
| `wiki/experimental-methods/` | 方法节点 | 参数、流程、排错、验证标准 |
| `wiki/research-directions/` | 方向节点 | 假设、灵感、问题、实验设计 |

用户可按主题在后三类目录中创建任意层级子文件夹，例如 `wiki/literature-synthesis/炎症/`。这只是你的浏览组织；链接与页面类型由顶层目录决定，不要把深层路径写成知识语义。

## 证据链

```text
Raw 条目 ──原始资料链接──► sources/来源页
                              │
                 supports / contradicts / 双链
                              ▼
              文献综合、实验方法、研究方向
```

知识页应把关键结论落回本地来源页，例如 `[[sources/某来源#关键观点]]`。外部链接主要留在 Raw frontmatter 或来源页“来源信息”中。这样即使外部网页失效，知识图谱仍保留本地证据线索。

## 前台与后台文件

- 经常打开：`notes/`、`raw/unprocessed/`、`wiki/index.md`。
- 自动维护：`raw/index.md`、`wiki/log.md`、Raw frontmatter。
- 仅在改变规则/目录/skill 时维护：`wiki/meta/History/`。
