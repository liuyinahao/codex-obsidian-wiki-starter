# 工作流总览

这个系统把“收集”和“理解”分开：Raw 保留证据，Wiki 保存可复用理解，用户在关键迁移点审阅。

```text
Safari Web Clipper / 用户笔记
            │
            ▼
     raw/unprocessed
            │  ingest-raw
            ▼
     pending_review ── 用户审阅与批准 ──► raw/processed
            │
            ├── wiki/sources（证据页）
            └── 三类知识页（综合 / 方法 / 方向）
```

## 两条入口

### 网页资料

1. 在 Safari 看到值得保存的网页。
2. 使用 Obsidian Web Clipper，保存到 `raw/unprocessed/`。
3. 对 Codex 说“ingest 下一条资料”或指定文件/批次。
4. Codex 创建来源页和相关 Wiki 页面，但只把 Raw 标为 `pending_review`。
5. 你查看 Wiki；确认后说“批准这次 ingest，归档到 processed”。

### 自己的课堂或方法笔记

1. 将笔记放入 `notes/class/` 或 `notes/method/`。
2. 对 Codex 说“整理这份笔记”。
3. Codex 只扩写正文，不改变你的标题大纲。
4. 你检查并自行返修；满意后说“接受这份笔记扩写”。
5. Codex 创建保留原笔记链接的 Raw 副本；以后按同一 ingest 流程沉淀到 Wiki。

## 为什么要有待审阅

`pending_review` 是内容检查点，不是故障状态。它让你在原始资料被归档、链接路径改变前，检查：

- Codex 是否理解了来源内容；
- 结论是否过度推断；
- 新建的 Wiki 页面是否放在合适的位置；
- Raw 与附件是否应作为一个批次处理。

这一步特别适合研究、课程和方法记录，因为它能把“AI 的初稿”与“你的最终知识库”明确分开。

## 重点 Clip 的范围规则

普通网页剪藏默认只读取本地剪藏 Markdown，避免每次都无边界地跟随链接。若标题末尾加字面 `*`，例如 `某篇关键论文 *`，则该条目是重点 Clip：Codex 会读取其关联图片、PDF、数据文件、视频与补充材料；参考文献链接仍不自动展开。

这样把阅读深度变成你保存资料时的一个轻量标记，而不是每次重复交代。
