# 首次运行：从空文件夹到第一次批准

## 0. 复制与打开

1. 复制启动包文件夹，按你的主题重命名，例如 `Research-Wiki`。
2. 在 Obsidian 选择“打开文件夹作为 Vault”。
3. 在 Codex 桌面端新建或打开本地项目，选择这个文件夹。
4. 对 Codex 说“先阅读 AGENTS.md 和 docs/03-首次运行.md，只读检查结构”。

首次对话让 Codex 明确读过规则，之后再开始放资料。

## 1. 做一次个人设置

打开 `AGENTS.md` 的“个人偏好：可由用户直接编辑”一节。先决定：

- 默认语言；
- 是否保留“冒号空位自动补全”；
- 标题末尾 `*` 是否作为重点资料标记；
- 你希望笔记扩写时如何处理不确定信息；
- 三个 Wiki 主题目录下你喜欢的分类方式。

详细做法见 [个性化设置](05-个性化设置.md)。改动工作流、目录或 skills 时，请要求 Codex 同时追加 `wiki/meta/History/` 记录。

## 2. 配置 Safari Web Clipper

在 Safari 的 Obsidian Web Clipper 模板或默认保存规则中：

- **Vault**：选择这个新 Vault；
- **保存路径**：`raw/unprocessed/`；
- **保存时不分类**：保持开启或不要按网站自动分目录；
- **标题**：保留网页标题。对关键资料可在保存后将标题末尾加 `*`。

不要把剪藏默认保存到 Wiki；Raw 才是入口。

## 3. 第一次网页 ingest

1. 选择一篇短网页，在 Safari 用 Web Clipper 保存。
2. 回到 Codex，输入：`ingest raw/unprocessed 中下一条资料。先说明判断与计划更新页面。`
3. 检查 Codex 是否：建立 `wiki/sources/` 来源页、更新一个合适的知识页、更新两个索引和日志。
4. 确认原资料仍在 `raw/unprocessed/`，但 frontmatter 为 `pending_review`。
5. 在 Obsidian 阅读新增 Wiki 页；满意后输入：`批准刚才的 ingest，归档到 processed。`
6. 检查资料进入 `raw/processed/`，且来源页的 Raw 链接仍可打开。

## 4. 第一次笔记扩写（可选）

1. 在 `notes/class/` 建一份含若干标题和速记的 Markdown 笔记。
2. 如想让 Codex 补齐某处，在中文冒号后留空，例如 `核心问题：`。
3. 输入：`整理 notes/class/这份笔记.md；保留全部标题层级和顺序。`
4. 检查正文是否成为可读笔记、标题是否没有被改动。
5. 需要沉淀进 Wiki 时，先自行修改确认，再输入：`我接受这份笔记扩写，请执行 note-approve。`
6. 后续再执行 ingest。

## 可选：Codex Panel

若想在 Obsidian 右栏使用 Codex Panel：在社区插件中安装后，把“Codex executable”设为本机 `codex` 可执行文件的绝对路径。面板的工作目录是当前 Vault 根目录。它适合短问答和就地维护；Codex 桌面端更适合管理多个项目与较长任务。无需安装此插件也可完整运行本启动包。
